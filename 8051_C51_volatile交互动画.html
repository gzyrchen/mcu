等级普通变量volatile

比喻的边界 · 六个易错点
  1. 不是 CPU 缓存陈旧。传统 8051 没有数据 cache。症结是编译器把「读 0x30」这条访问移出循环或判定为恒值，生成的代码压根不再读内存；错误发生在编译期。
  2. 不是「必然」卡死。C 标准只保证 volatile 的语义；对普通变量，编译器允许假定没有程序之外的修改。是否真的优化、优化到什么程度，取决于 Keil Cx51 版本、优化等级与代码形态。等级 0 / 1 常「碰巧能跑」，但代码依然不正确。
  3. volatile 不保证原子性。C51 的 int 是 16 位，8 位内核要分两字节读；中断插在中间会读到撕裂值。flag++ 是读—改—写三步，即便 8 位也可能丢更新。多字节共享量或自增操作仍需关中断／临界区。
  4. volatile 不是内存屏障。它只要求对该对象每次真实访问、且不删不合并；不保证不同 volatile 对象之间的相对顺序，也不保护其它无关变量，不能当同步原语用。
  5. SFR 不必再加。REG51.H 中由 sfr / sbit 定义的对象由编译器特殊处理，天然每次真实读写。只有自己用指针映射的硬件寄存器、以及 ISR 与 main 共享的普通变量才需要显式写 volatile。
  6. 有代价。volatile 禁止相关优化，频繁访问会多出读／写内存动作，在 8051 上是几个机器周期量级。正确性优先，但不必给所有变量都加。
哪些对象必须加 volatile
  1. ISR 与主循环共享的标志：本页的 flag；反向（main 写、ISR 读）同理。
  2. 硬件会自行改动的寄存器：用绝对地址指针访问的串口／定时器状态寄存器等。
  3. 多任务／RTOS 共享量：被另一执行流修改且无法被编译器看见的对象。
  4. 顺带一提：const 管「本程序不改」，volatile 管「别人会改」，两者可以叠加（如只读状态寄存器）。
这张图对应哪些考点
  1. 解释「调试时正常、开优化后死机」「单步能过、全速卡住」这类典型现场故障。
  2. 区分「编译期优化」与「运行期竞态」：前者靠 volatile，后者靠临界区。
  3. C51 数据类型位宽：int 为 16 位，多字节访问非原子。
  4. 优化等级是编译选项，不改变源码；同一份 .c 在不同等级下行为可能不同。
  5. 图中的 tmp = flag; while(!tmp); 是C 级等价行为示意，用来说明「只读一次内存」的后果，并非 Keil Cx51 生成的汇编或机器码；C51 课不要求读汇编。
