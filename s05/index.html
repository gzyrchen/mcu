比喻的边界 · 六个易错点
  1. 不是 4 位同时点亮。任一瞬间只有 1 位被选中，每位占空比固定 1/4；靠 LED 余辉与人眼视觉暂留把分时显示「积分」成同时显示，长延时就能看到逐位跳。
  2. 消隐不是为了省电。它是避免「段码先变、位选后变」的一瞬串位。这一瞬只有几条 C 语句的极短时间，但每秒重复上百次，人眼累积后就是稳定的错误笔画。
  3. 提高刷新率不会更亮。占空比始终 1/4，变的只是闪烁感；亮度靠段电流与限流电阻，峰值电流不得超过 I/O 与 LED 额定值，位选驱动还要能扛 8 段总电流。
  4. code 不是「存到芯片外」。它把常量放进程序空间（Flash / ROM），运行时只读；不加 code 才落片内 RAM，10 B 表还要启动时复制初值，对 128 / 256 B 片内 RAM 是浪费。
  5. 段码不是通用常数。共阴 0 是 0x3F，共阳按位取反为 0xC0；段线顺序、反相驱动、是否带 dp 都会改表，必须对着原理图推，别背表。
  6. 软件延时占着 CPU。工程上用 T0 定时中断刷新；显示缓冲被 ISR 与主程序共享时要 volatile，多字节量还要考虑一致性，delay_ms() 被中断打乱会造成亮度不匀。
段码表怎么推 · 极性与消隐电平
  1. 按 a,b,c,d,e,f,g 对应 P0.0~P0.6 写出每个数字该亮的段，得到一个字节；例如 0 亮 abcdef、不亮 g、dp → 0x3F。
  2. 共阳极段线低电平点亮，把共阴段码按位取反即可：0x3F → 0xC0，0x06 → 0xF9。字形相同，只是端口电平相反。
  3. 消隐有两种做法：本页用「关位选」P2 = 0x00，与管型无关；也可送「段全灭码」，共阴 P0 = 0x00、共阳 P0 = 0xFF。两种别混用，尤其别把共阴的 0x00 照搬到共阳，那反而是全亮。
  4. 本页为突出段码与消隐，约定位选经反相驱动、写 1 选中。实际板卡共阳极位选常为低有效，需按原理图改 P2 表达式，不要照抄。
这张图对应哪些考点
  1. 由位数与每位延时算一轮周期、刷新率与占空比，并判断是否闪烁（经验判据 ≥ 50 Hz）。
  2. 解释「鬼影／串位／拖影」的成因，写出正确的切换顺序，指出少哪一行会出问题。
  3. code 关键字与 8051 程序空间 / 数据空间分开的哈佛结构，说明为何常量表要放程序空间。
  4. 共阴 / 共阳段码推导、按位取反，以及段线接法变化对表的影响。
  5. 软件延时扫描与定时器中断刷新的取舍；共享显示缓冲的正确声明。
  6. 图中「教学慢放」把每条语句放大成可观察的一步；真实切换只有微秒量级，保持时间才是 t ms。
