访问代价对比

按传统 12T 内核的典型机器周期示意。data / idata / bdata 同为 1 周期，差别在寻址方式与指令字节数；xdata / code 为 2 周期，因需走外部总线。1T 内核（如 STC12/15）数值不同，但相对关系不变。

比喻的边界（务必讲给学生）
  1. 不是五个仓库。data、idata、bdata 指向同一块片内 RAM 的不同部分/不同寻址方式；bdata 只是 20H–2FH 这 16 个字节的「按位看」视图。
  2. 「远」不是距离，是指令与总线。xdata 慢是因为外部访问要走 P0/P2 总线、多耗一个机器周期，不是数据跑得更远。
  3. code 并非物理上永不可写。带 IAP 的 8051 可用特殊流程擦写 Flash，但对普通 C 变量，运行时一律只读。
  4. C51 课不要求记指令。底层由编译器按存储区生成不同总线周期，只需记住「存储区不同 → 通道不同 → 机器周期不同」这条因果链。
  5. 真实工程由编译器决定默认落点。未写存储类型时按 small / compact / large 模式自动分配；动画里的「拖到哪放哪」是教学简化。

bdata 位寻址区 · 20H–2FH

16 字节 × 8 位 = 128 个可独立寻址的位（位地址 00H–7FH）。点任意格子执行置位 / 清零，观察 sbit 与位地址的对应关系。

unsigned char bdata flags;  sbit ready = flags^0; // 位地址 00H

边界：位寻址是「同一批字节的另一种看法」，不是另开了一块存储区；bit 变量总数超过 128 个会编译失败。
